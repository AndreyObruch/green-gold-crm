# Green Gold CRM: Удалённый доступ (Remote Access)

## 1. Текущая архитектура и риски

CRM работает локально на порту `3000` (`http://172.25.46.103:3000`).
Данные хранятся в файле `db/crm.db` и папке `uploads`.
Авторизация — JWT-токены, пароли хешируются bcrypt.

**Критическое предупреждение:**
Прямое пробрасывание порта `3000` из интернета (Port Forwarding / NAT) **ЗАПРЕЩЕНО** без дополнительной защиты уровня TLS/SSL и WAF.
Причины:
1. HTTP трафик не шифруется: логин, пароль и токены перехватываются в открытом виде.
2. SQLite DB и файлы Uploads становятся мишенью для автоматических сканеров уязвимостей.
3. Отсутствие Rate Limiting на уровне сервера делает возможным брутфорс или DoS.

## 2. Рекомендуемые варианты удалённого доступа

### Вариант A: VPN (Туннель) — Безопасный стандарт
Участники подключаются к внутренней сети через защищённый канал, а затем обращаются к `localhost:3000` или внутреннему IP как обычно.

*   **Инструменты:** WireGuard, OpenVPN, Tailscale, ZeroTier.
*   **Плюсы:** Полное шифрование, скрытие CRM от интернета, контроль доступа на уровне устройства.
*   **Минусы:** Требует настройки клиента на устройстве пользователя.
*   **Реализация:**
    1. Поднять VPN-сервер на том же ПК или отдельном VPS.
    2. Разрешить трафик к `172.25.46.103:3000` только из интерфейса VPN.
    3. Пользователи получают виртуальный IP и открывают адрес в браузере.

### Вариант B: Reverse Proxy + HTTPS (Cloudflare Tunnel / ngrok)
Безопасная туннелизация трафика с внешним сервисом, который обеспечивает SSL и защиту от DDoS.

*   **Инструменты:** Cloudflare Tunnel (`cloudflared`), ngrok, frp.
*   **Плюсы:** Не нужно открывать порты роутера, бесплатный SSL, сокрытие реального IP.
*   **Минусы:** Зависимость от внешнего сервиса, возможная задержка (latency).
*   **Реализация (пример Cloudflare):**
    1. Создать аккаунт Cloudflare Zero Trust.
    2. Установить агент `cloudflared` на сервере CRM.
    3. Настроить туннель на `http://localhost:3000`.
    4. Привязать домен (например, `crm.mydomain.com`).
    5. Включить SSO (Single Sign-On) или Access Policy в Cloudflare, чтобы ограничить вход списком email сотрудников.

### Вариант C: SSH Port Forwarding (Для админов/разработчиков)
Временный доступ для диагностики.

*   **Команда на клиенте:** `ssh -L 3000:localhost:3000 user@server-ip`
*   **Адрес в браузере:** `http://localhost:3000`
*   **Плюсы:** Максимальная безопасность, не требует открытия портов.
*   **Минусы:** Сложно для обычных пользователей, требует установки SSH-клиента.

## 3. Обязательные меры безопасности при любом варианте

Если выбирается вариант B (Reverse Proxy) или прямой доступ (не рекомендуется):

1.  **HTTPS/TLS обязателен.** Никакого чистого HTTP в интернете.
2.  **Rate Limiting.** Добавить ограничение частоты запросов (например, через Nginx/Apache перед Node.js или middleware `express-rate-limit`), чтобы защитить `/api/auth/login` от брутфорса.
3.  **Strong Passwords.** Принудительная сложность паролей при регистрации/смене.
4.  **Backup Strategy.** Автоматическое резервное копирование `crm.db` и `uploads` во внешнее облако/S3, так как локальный диск может выйти из строя.
5.  **Audit Log Monitoring.** Регулярный просмотр таблицы `audit_log` на предмет подозрительных действий (необычные IP, массовые удаления).

## 4. План действий

1.  Определить круг лиц, которым нужен удалённый доступ.
2.  Выбрать инструмент (рекомендуется **Tailscale/WireGuard** для простоты и безопасности или **Cloudflare Tunnel** для удобства пользователей).
3.  Настроить туннель/VPN.
4.  Протестировать доступ извне локальной сети.
5.  Обновить инструкцию `README.md` для коллег с новым способом входа.
